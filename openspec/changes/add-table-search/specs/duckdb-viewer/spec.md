# Spec Delta

## ADDED Requirements

### Requirement: 按名称搜索表、视图与列

系统 SHALL 在查看器左侧栏提供搜索输入框，并基于已加载的 schema 元数据，对表名、视图名和列名进行不区分大小写的子串匹配。查询按空白拆分为多个词时，所有词 MUST 同时命中才算匹配。

- 对象（表/视图）的匹配范围是 `schema.对象名`；列的匹配范围是 `schema.表名.列名`。
- 列结果 MUST 额外满足：至少一个查询词命中列名本身，避免搜索表名时把该表的所有列都列为结果。
- 搜索 MUST NOT 读取数据库，也 MUST NOT 改变当前选中对象、排序、过滤或已加载的数据页。
- 结果 MUST 按匹配质量确定性排序：完全匹配先于前缀匹配，前缀匹配先于其他子串匹配；同一质量下对象先于列，再按 schema、名称、列序号排序。
- 匹配结果超过 200 条时，系统 MUST 只展示前 200 条，并标明匹配总数与"仅显示前 200 条"。

#### Scenario: 按表名搜索

- **WHEN** 用户在搜索框输入 `orders`
- **THEN** 结果列表展示所有限定名包含 `orders` 的表与视图，并标明其 schema 与类型
- **AND** 当前网格中的数据保持不变，直到用户选择某条结果

#### Scenario: 多词搜索

- **WHEN** 用户输入 `order user`
- **THEN** 只有名称同时包含 `order` 与 `user` 的对象或列出现在结果中

#### Scenario: 按列名搜索

- **WHEN** 用户输入 `email`
- **THEN** 结果中列出名称包含 `email` 的列，并同时展示其所属的表/视图与数据类型
- **AND** 即使该表名本身不匹配，这些列结果仍然出现

#### Scenario: 表名命中时不列出无关列

- **WHEN** 用户输入的词命中了表名，但没有命中该表的任何列名
- **THEN** 结果只包含该表本身，不把它的所有列作为列结果列出

#### Scenario: 无匹配

- **WHEN** 查询没有匹配任何表、视图或列
- **THEN** 系统展示"没有匹配的表、视图或列"的空状态，并保留用户输入的查询

#### Scenario: 结果超过上限

- **WHEN** 匹配项超过 200 条
- **THEN** 系统展示前 200 条，并显示匹配总数与"仅显示前 200 条"的提示

#### Scenario: 清空搜索

- **WHEN** 用户清空搜索框或按 Esc
- **THEN** 左侧栏恢复为正常的 schema 树，搜索前展开/折叠的状态得以保留

### Requirement: 从搜索结果跳转

系统 SHALL 允许用户从搜索结果直接跳转到表/视图或具体列。搜索框与结果列表在选择结果后 MUST 保持可见，以便连续跳转。

#### Scenario: 打开对象结果

- **WHEN** 用户点击一条表或视图搜索结果
- **THEN** 该对象被选中，网格展示其第一页数据
- **AND** 与该对象相关的排序与过滤被重置，行为与在树中直接选择对象一致

#### Scenario: 跳转到列

- **WHEN** 用户点击一条列搜索结果
- **THEN** 系统选中该列所属的表或视图并加载其数据
- **AND** 树中该对象被展开，对应列被突出显示并滚动到可见区域

#### Scenario: 高亮的清除

- **WHEN** 用户随后选择了其他对象、清空了搜索或关闭了结果列表
- **THEN** 列高亮不再显示

#### Scenario: 列属于视图

- **WHEN** 列结果来自一个视图
- **THEN** 使用与表相同的跳转行为，并能正常展示该视图的数据

### Requirement: 搜索结果的键盘操作

系统 SHALL 支持用键盘完成搜索与跳转，并始终以可见方式标识当前活动结果。

#### Scenario: 移动活动结果

- **WHEN** 搜索框获得焦点且存在结果，用户按 ↓ 或 ↑
- **THEN** 活动结果在列表中向后或向前移动，并以可见样式区别于其他结果

#### Scenario: 用 Enter 打开

- **WHEN** 用户按 Enter
- **THEN** 系统打开当前活动结果；若尚未有活动结果，则打开列表中的第一条

#### Scenario: 没有结果时按 Enter

- **WHEN** 搜索没有匹配结果时用户按 Enter
- **THEN** 系统不改变当前选中对象或数据
