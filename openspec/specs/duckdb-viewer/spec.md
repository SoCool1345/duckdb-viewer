# duckdb-viewer Specification

## Purpose
让用户直接在 VS Code 中打开 DuckDB 数据库文件，浏览其 schema、表与视图的数据，而无需编写 SQL 或离开编辑器。该能力只覆盖观察，不覆盖修改。

## Requirements

### Requirement: 以只读编辑器打开数据库文件

系统 SHALL 允许用户从资源管理器上下文菜单或命令面板打开 `.duckdb` / `.ddb` 文件，并在一个只读自定义编辑器标签页中展示其内容。

该编辑器 MUST NOT 成为这些文件类型的默认打开方式；用户需显式选择 "Open With" 或在设置中启用默认关联。

#### Scenario: 通过上下文菜单打开

- **WHEN** 用户在资源管理器中右键一个 `.duckdb` 文件并选择查看器
- **THEN** 系统在编辑器区打开该文件的只读标签页，标题显示文件名与"只读"标识
- **AND** 左侧展示该库的 schema 树

#### Scenario: 同一文件不重复打开

- **WHEN** 该文件的标签页已经打开，用户再次请求打开同一文件
- **THEN** 系统聚焦已有标签页，而不是创建第二个编辑器实例

#### Scenario: 非 DuckDB 文件

- **WHEN** 用户对一个不是 DuckDB 数据库的文件使用该查看器
- **THEN** 编辑器展示明确的错误说明，指出文件无法按 DuckDB 格式解析
- **AND** 系统不修改该文件

### Requirement: 浏览 schema 结构

系统 SHALL 在编辑器中展示数据库的 schema 层级：schema → 表/视图 → 列，并展示每个列的名称、数据类型与可空性。

#### Scenario: 展示表与视图

- **WHEN** 数据库包含多个 schema、表和视图
- **THEN** 树中按 schema 分组列出所有表与视图，并区分二者的类型
- **AND** 系统内部使用的系统 schema 不作为普通表呈现给用户

#### Scenario: 展示列信息

- **WHEN** 用户展开一个表节点
- **THEN** 系统列出该表的所有列，每列显示名称、数据类型和是否可空

#### Scenario: 空数据库

- **WHEN** 数据库中没有任何用户表
- **THEN** 编辑器展示空状态说明，而不是空白面板或错误

### Requirement: 分页浏览表数据

系统 SHALL 以分页方式展示所选表或视图的数据，单页行数可配置，并提供上一页/下一页导航与页码信息。

#### Scenario: 打开表显示首页

- **WHEN** 用户选中一个表
- **THEN** 系统在网格中展示该表的第一页数据与列头
- **AND** 展示总行数的估算值，并标明该值为估算

#### Scenario: 翻页

- **WHEN** 用户请求下一页
- **THEN** 系统展示紧随其后的若干行，并更新页码与是否还能继续翻页的状态

#### Scenario: 排序下的分页稳定性

- **WHEN** 用户已对某列排序并翻页
- **THEN** 同一排序键下的行顺序在页与页之间保持稳定，不出现重复或整行遗漏

#### Scenario: 无法保证稳定顺序

- **WHEN** 当前对象不提供可用于稳定分页的排序依据
- **THEN** 系统在该对象的浏览界面标注"顺序不保证稳定"，而不是静默呈现可能重复的行

### Requirement: 对数据进行排序与过滤

系统 SHALL 允许用户按列排序（升序/降序/取消排序），并支持按单列进行基础过滤。

#### Scenario: 按列排序

- **WHEN** 用户点击某列列头切换排序
- **THEN** 系统按该列重排数据并回到第一页
- **AND** 网格中显示当前排序方向

#### Scenario: 应用列过滤

- **WHEN** 用户为某列设置过滤条件
- **THEN** 系统只展示满足该条件的行，并把分页重置到第一页
- **AND** 用户可以清除该过滤以恢复未过滤视图

#### Scenario: 过滤无匹配

- **WHEN** 过滤条件匹配不到任何行
- **THEN** 系统展示"无匹配数据"的空状态，并保留当前过滤条件可见

### Requirement: 提示外部数据变更

当数据库文件在查看器之外被修改时，系统 SHALL 提示用户当前展示的数据可能已过期。

#### Scenario: 检测到外部写入

- **WHEN** 数据库文件在两次数据读取之间发生变化
- **THEN** 编辑器展示可见提示，说明数据可能已变化
- **AND** 提供手动刷新操作

#### Scenario: 刷新后提示消失

- **WHEN** 用户执行刷新且数据成功重新读取
- **THEN** 提示消失，展示内容对应最新的数据库状态

### Requirement: 以可读形式呈现各类数据

系统 SHALL 将 DuckDB 的各类值呈现为可读文本，且不得因显示而损失精度或改变含义。

#### Scenario: 高精度数值

- **WHEN** 某列类型为 DECIMAL、HUGEINT 或 UUID
- **THEN** 系统以其完整文本形式展示，不经过浮点转换

#### Scenario: 嵌套类型

- **WHEN** 某列类型为 STRUCT、LIST 或 MAP
- **THEN** 系统以结构化的可读文本展示其内容，而不是显示为不可读的占位符

#### Scenario: 二进制大对象

- **WHEN** 某列类型为 BLOB 且内容较大
- **THEN** 系统展示长度信息与截断后的预览，而不是整块原始字节

#### Scenario: 空值

- **WHEN** 单元格值为 NULL
- **THEN** 系统以区别于空字符串的可见方式标示该值为空

### Requirement: 明确报告打开与查询失败

系统 SHALL 在无法打开数据库或读取数据时，向用户提供可理解的原因与后续操作，而不是仅抛出底层错误文本。

#### Scenario: 数据库版本过新

- **WHEN** 数据库文件由比当前查看器更新的 DuckDB 版本创建，因而无法读取
- **THEN** 系统说明这是版本不兼容，并给出可执行的指引（如升级查看器）
- **AND** 不尝试以任何方式改写该文件

#### Scenario: 文件损坏或不可读

- **WHEN** 打开数据库时发生 I/O 或解析错误
- **THEN** 编辑器展示错误详情与"重试"入口，并保持标签页可用以便重新尝试
