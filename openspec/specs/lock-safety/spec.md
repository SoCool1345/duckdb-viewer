# lock-safety Specification

## Purpose
定义查看器与 DuckDB 数据库文件之间的锁契约，使得打开一个数据库进行浏览时，不会阻止其他进程对该库的写入，也不会在异常退出后留下占锁的残留进程。

## Requirements

### Requirement: 静止时不得持有数据库句柄

查看器 MUST 仅在单次数据操作的执行期间持有数据库文件句柄，操作结束后立即释放。不存在"打开着的会话"这一状态。

#### Scenario: 空闲时可被外部进程写入

- **WHEN** 用户正在查看某个库的某张表，且查看器当下没有正在执行的操作
- **THEN** 另一个进程可以以读写方式打开同一数据库并成功写入

#### Scenario: 翻页之间外部写入成功

- **WHEN** 用户浏览第一页后请求第二页，两次请求之间存在外部写入进程
- **THEN** 外部写入成功完成
- **AND** 查看器的下一次读取能够读到该写入的结果

#### Scenario: 关闭标签页后立即可写

- **WHEN** 用户关闭数据库标签页
- **THEN** 另一个进程可以在无需等待的情况下以读写方式打开该数据库

#### Scenario: 只读查看器之间共存

- **WHEN** 同一个数据库文件在两个 VS Code 窗口中分别以查看器打开
- **THEN** 两个窗口都能正常读取数据，且互不报锁冲突

### Requirement: 访问必须是只读的且不改写数据库文件

查看器 MUST NOT 对数据库执行任何写操作，也 MUST NOT 触发会改变数据库文件或 WAL 文件的维护动作（如 checkpoint）。

#### Scenario: 浏览不改变文件内容

- **WHEN** 用户浏览若干表与若干页数据后关闭查看器
- **THEN** 数据库文件与 WAL 文件的内容不被查看器改变

#### Scenario: 读取未 checkpoint 的数据

- **WHEN** 数据库存在未并入主文件的 WAL，且其中包含已提交的写入
- **THEN** 查看器能够读到这些已提交的数据
- **AND** 查看器不合并、不清空该 WAL 文件

#### Scenario: 拒绝写入意图

- **WHEN** 任何操作路径试图对数据库执行写入语句
- **THEN** 该操作被拒绝并报告为错误，数据库保持不变

### Requirement: 占用冲突必须可见且可恢复

当数据库被另一个进程以读写方式占用而无法打开时，查看器 MUST 说明占用方身份，并允许用户在占用解除后继续，而不是让用户面对原始错误文本。

#### Scenario: 报告占用者

- **WHEN** 打开数据库失败并被告知文件已被其他进程打开
- **THEN** 查看器展示占用者的进程标识与可读的进程名
- **AND** 提示这是 DuckDB 的并发限制，而非文件损坏

#### Scenario: 等待占用解除后自动继续

- **WHEN** 用户选择"等待释放"，且占用随后被解除
- **THEN** 查看器在无需用户再次操作的情况下完成打开并展示内容

#### Scenario: 放弃等待

- **WHEN** 用户取消"等待释放"
- **THEN** 查看器停止探测，保留可重试的界面，且不产生后台轮询负担

### Requirement: 单次操作的锁窗口必须有界

任何由查看器发起的数据库操作 MUST 可以被用户取消，并且取消后 MUST 在有限时间内释放数据库句柄。正在执行的操作不得无上限地占用数据库。

#### Scenario: 取消进行中的查询

- **WHEN** 用户对一个长时间运行的读取操作执行取消
- **THEN** 该操作停止，界面恢复到可继续浏览的状态
- **AND** 数据库句柄在数秒内被释放

#### Scenario: 超时后被放弃

- **WHEN** 一次读取超过了配置的操作时限
- **THEN** 系统放弃该操作并释放句柄，同时向用户说明是超时导致的失败

#### Scenario: 一键释放

- **WHEN** 用户执行"释放数据库锁"命令
- **THEN** 所有正在进行的操作被取消，且查看器不再持有任何数据库句柄

### Requirement: 查看器不得比编辑器宿主存活更久

查看器的数据库访问进程 MUST 在编辑器宿主终止后短时间内自行退出，MUST NOT 因宿主崩溃、被强制结束或升级而残留并继续占用数据库文件。

#### Scenario: 宿主被强制结束

- **WHEN** 扩展宿主进程被强制杀死
- **THEN** 访问进程在数秒内自行退出
- **AND** 数据库文件随之变为可被其他进程读写打开

#### Scenario: VS Code 正常关闭

- **WHEN** VS Code 正常关闭
- **THEN** 访问进程随之退出，不留下后台进程

#### Scenario: 访问进程意外死亡

- **WHEN** 数据库访问进程异常退出
- **THEN** 查看器在下一次操作时自动恢复可用状态，并向用户说明刚才发生了中断

### Requirement: 锁状态对用户可见且可诊断

查看器 SHALL 让用户随时确认自己是否正在占用数据库，并在需要时提供可用于排障的信息。

#### Scenario: 状态栏指示

- **WHEN** 数据库标签页处于打开状态
- **THEN** 状态栏或编辑器标题显示当前是否持有数据库锁

#### Scenario: 诊断查询

- **WHEN** 用户请求锁诊断信息
- **THEN** 系统报告当前打开的数据库句柄数量与对应文件路径
- **AND** 在空闲状态下该数量为 0
